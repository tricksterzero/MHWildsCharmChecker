# タスク: MHWilds 護石スクショ読み取り(未処理分の増分処理版)

## 概要
このタスクは Cowork の登録済みタスクとして**無人で実行される**前提で書かれている。実行時にチャットで日付や引数を受け取ることはできない。代わりに「処理済みマーカー」ファイルで前回までの処理位置を記録し、**前回以降に増えたスクリーンショットだけ**を読み取って CSV 化する。定期実行・手動(Run now)実行のどちらでも同じ挙動になる。

## 入力・パス
- **スクリーンショットフォルダ**: `C:\Program Files (x86)\Steam\userdata\39293390\760\remote\2246340\screenshots`
- **正規化辞書**: `C:\File\Program\MHWildsCharmChecker\skill-decoration-map.json`
- **処理済みマーカー**: `C:\File\Program\MHWildsCharmChecker\charm_reader_state.json`
- **出力フォルダ**: `C:\File\Program\MHWildsCharmChecker\out\`(無ければ作成。実行ごとに新規ファイル `charm_YYYYMMDD_HHMMSS.csv` を作る)

## 実装上の原則
- **ファイルの選別とマーカーの更新は、視覚判断ではなくコード(スクリプト)で決定論的に行うこと。** 画像の内容(スキル名・レベル・スロット)の読み取りのみ視覚で行う。
- マーカーファイルの形式:
  ```json
  { "last_processed": "<ファイル名>", "updated_at": "<ISO8601>" }
  ```
- **比較順序**: ファイル名先頭14桁 `YYYYMMDDHHMMSS` を主キーに**数値**比較し、同一秒内は末尾 `_n` の `n` を**数値**比較する(文字列比較だと `_10` と `_2` の順序が狂うため、必ず数値で比較すること)。

## 処理手順

### 0. マーカー読み込みと初回判定
- マーカーファイルが存在しない場合は「**初回**」とみなす。スクショフォルダ内の最新画像ファイル名を `last_processed` に記録してマーカーを作成し、**画像は一切処理せずに終了する**(「マーカーを初期化、処理0件」とログに記録)。
  - 理由: スクショフォルダには護石以外の過去スクリーンショットが大量に含まれ得るため、初回に全件処理すると暴発する。過去分を遡って処理したい場合は、マーカーの `last_processed` を目的の時刻の直前のファイル名に手動で書き換えてから再実行する。

### 1. 対象ファイルの抽出
- フォルダ内の画像ファイル(`.jpg` / `.jpeg` / `.png`)のうち、上記比較順序で `last_processed` より**厳密に新しい**ものを抽出し、昇順に並べる。これを処理候補とする。
- 処理候補が0件なら「新規スクショなし、処理0件」とログに記録し、**マーカーは据え置いたまま終了**する(手順4のマーカー更新は行わない)。

### 2. 各画像の読み取り(1画像=護石1個前提)
処理候補を1枚ずつ処理する。各画像から「装備詳細」パネルを探し、以下を読み取る。
- **スキル**: 「装備スキル」欄のスキル名とレベルを、**画面表示の上から順に**列挙する(最大3つ)。
- **スロット**: 「スロット」欄の各スロットについて2要素を判定する。
  - **レベル**: 穴の下部の三角形の数。三角1個=Lv1、2個=Lv2、3個=Lv3。
  - **種別**: アイコン右肩のマーク。剣=武器スロット、兜=防具スロット。

### 3. 正規化と確度チェック(厳格)
- 読み取ったスキル名を、`skill-decoration-map.json` の `decorations[].skills` キーに含まれる正規スキル名と照合する。**全角・半角・記号を正規化した上で完全一致したもののみ採用**する(例: 辞書側「体力回復量ＵＰ」に対し、半角 `UP` 読み取りは全角化して一致判定)。
- 完全一致しない場合は**そのスキルを採用しない**。最近傍候補があれば参考として警告に併記してよいが、**自動補正はしない**。
- 装備詳細1セットを明確に読み取れない画像(護石以外の画面・複数個写り・判別困難)、またはスロットの三角数/種別アイコン・スキル名/レベルに**確度の低い項目が1つでもある護石は採用しない**。当該画像をスキップ扱いとし、ファイル名と理由を警告に記録する。

### 4. 出力とマーカー更新
- 採用した護石の CSV 行を、出力ファイル `out\charm_YYYYMMDD_HHMMSS.csv` に1行ずつ書き出す。同じ内容をセッションログ(チャット)にも出力する。
- 出力末尾に以下を記載する:
  - 警告一覧(ファイル名 + 理由)
  - 集計: 処理候補件数 / 採用件数 / 警告(スキップ)件数
- **マーカー更新**: 今回の処理候補のうち最も新しいファイル名を `last_processed` に上書き保存し、`updated_at` を現在時刻に更新する。
  - これにより、採用・スキップに関わらず**走査済みのファイルは次回以降の対象から外れる**。スキップされたスクショは警告ログから手動で対応する(必要ならそのファイルだけ手動処理するか、マーカーを巻き戻して再実行する)。

## CSV形式
1行 = 護石1個。カンマ区切り12列。

```
スキル1名,スキル1Lv,スキル2名,スキル2Lv,スキル3名,スキル3Lv,防具スロット1Lv,防具スロット2Lv,防具スロット3Lv,武器スロット1Lv,武器スロット2Lv,武器スロット3Lv
```

- スキルが3つ未満の場合、空きスキルは名前を空欄、レベルを `0` とする。
- スロットは各位置のレベルを `0/1/2/3` で記録する(穴が無い位置は `0`)。

### 出力例
```
通常弾・通常矢強化,1,挑戦者,1,,0,1,1,0,1,0,0
```
スキル1=通常弾・通常矢強化Lv1、スキル2=挑戦者Lv1、スキル3=空、防具スロット ①① 、武器スロット ① 。
